
**API documentation** is the information provided to help developers understand how to integrate with and correctly use an API.

It describes the API's available functionality, expected inputs and outputs, authentication requirements, data structures, errors, and usage conventions.

---
## Key Ideas

- API documentation acts as the **interface between an API and its consumers**, allowing developers to understand how to use the API without needing knowledge of its internal implementation.
	
- **API references** document the concrete API surface, such as endpoints, operations, parameters, request bodies, response structures, and status codes.
	
- Good documentation often includes **examples and usage guidance** in addition to raw technical specifications, helping consumers understand how different parts of the API are intended to be used.
	
- Documentation should describe **authentication and authorization requirements** so consumers know how credentials or tokens must be supplied.
	
- **Error documentation** explains possible failure responses and gives consumers enough information to correctly handle them.
	
- API documentation should remain synchronized with the actual API. Outdated documentation can be worse than missing documentation because consumers may build integrations against behavior that no longer exists.
	
- Machine-readable API descriptions can be used to **generate documentation and tooling automatically**, reducing duplication between an API's implementation and its documentation.
